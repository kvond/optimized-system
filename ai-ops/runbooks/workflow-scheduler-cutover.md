# Contract invocation and scheduler cutover

The canonical private scheduler registry is the sole inventory. A private
candidate bundle is a proposed edit plus preserved rollback evidence, not another
registry, active schedule, successful run or authority grant. Exact provider IDs,
TOMLs, prompt bodies, accounts, locations and hashes belong outside Git. Never
infer active ownership from a contract title or from a historical task receipt.

## Same-owner prompt conversion

1. Read the one current registry entry and exact native definition. Preserve its
   complete bytes outside Git. Keep name, target chat, cadence, status, notification
   preferences, account, environment and any model selection exactly unchanged.
   A daily requested output still runs daily even if routine progress is quiet.
2. Compare every original policy paragraph to the versioned definition and
   procedures. Record exact source hashes and reviewed mappings privately.
   Supersession must name the later teacher instruction, not silently discard
   conflicting old text. A shape/coverage check is not semantic equivalence.
3. Pin exact contract version/content and all required procedure content. Publish
   the reviewed release to the canonical private repository and verify the
   actual execution checkout can read it. A temporary reviewer worktree is not
   a permanent scheduler dependency. Do not update a prompt first and hope its
   referenced code appears later. Rebuild the candidate if any pinned rule changes.
4. Resolve private input, output, account, current authority and receipt bindings.
   An identity-check CLI only validates files; then the executor must read the
   returned procedures and current governing references and perform the workflow.
   The same target chat retains pending numbered questions. Answers resume the
   exact issue immediately after a source refresh; a passed write window carries
   only dependent writes to the already-existing safe window.
5. Have a fresh session use the exact short invocation and verify the correct
   bounded native output. Record which parts were read-only or synthetic; an
   artifact check does not prove real grading/email/source behavior. Do not run
   consequential production actions just to test scheduler conversion.
6. Immediately before an authorized edit, ensure no run owns the job; reread the
   complete native definition and compare its preserved source hash. Only the
   coordinator performs the existing job update. Do not create a replacement for
   a prompt-only conversion. Use the exact private update payload via the native
   scheduling tool, never direct TOML editing as a scheduling mechanism.
7. Read back the whole definition. Only prompt and backend-managed timestamp may
   differ. Check notification policy, target thread, status and recurrence, not
   just displayed title. Reconcile the existing registry record with its accepted
   new source hash; retain its original rollback reference. Preserve a native
   receipt separately and set the candidate's `accepted_definition_sha256` to
   that exact readback. The invocation checks the live definition against the
   same registry record; stale metadata blocks execution. Watch the first
   scheduled output before claiming success.

## Destination migration

Moving execution is separate from contracting an existing local owner. No local
path can make an unconnected cloud task run code. A verified home-Mac code session
does not establish school-computer or School Claude capability. Quota-exhausted
Desktop Commander remains unavailable; native/API alternatives need the exact
destination/account/operation trial. Independently running sessions share sources
and must participate in ownership checks.

Keep the existing proven owner until the actual intended destination has accepted
the bounded trial, exact inputs/output, timezone, cadence, private access, runtime
and native result readback. Prepare the destination inactive only when its creation
is authorized. Do not invent provider fields that a UI or API has not exposed.
Do not enable disabled discovery APIs or recreate paused/declined work.

At cutover, the coordinator rereads both owners and obtains the shared lease.
Disable the old owner, then obtain native readback that it is disabled. Only then
enable the already-tested replacement and read back both states and its output.
Unknown old state blocks enabling the replacement. Unknown new state blocks
restoring the old one. Do not use absence of a receipt as proof a writer is idle.

If acceptance fails before cutover, leave the old owner running and destination
inactive. If it fails after cutover, disable/read back the replacement before
restoring the exact preserved old definition and reading back that single owner.
A rollback never repeats a grade save, email, provider operation or publication.
Reconcile uncertain outputs using their original request, reservation, versions
and native destination; preserve the existing recovery block. At most one owner
may be active. If state cannot be read, stop further mutations and report one
exact reconciliation action.

## Current scope boundaries

The preparation/helper/feedback/follow-up sequence keeps its existing owners.
Before-07:00 source changes remain in preparation. The existing helper is the sole
grade writer. Feedback keeps the current teacher-only outbox, one-use send fence,
expiry, exact MIME readback and no uncertain resend; current confirmed email
supersedes the older generic Hub Print direction. Printed/Handed remain teacher
controlled. Code or UI repair after cutoff must not race frozen school sources.

The private binding evidence preserves the exact current adapter/runtime paths,
its supported action/request/result shapes and existing confirmed correction
seed. Resolve those implementation details before the outbox is used; a generic
email action does not satisfy that contract. Preserve the existing source intake
folder even after copies exist, leave retired answer spreadsheets retired and
never mark live Form sources for deletion. Retain each distinct source revision,
the existing index/navigation binding, and teacher reports separate by class
with the existing cycle-number prefix (or `00` for general reports).

For science-writing, the later format controls: use saved attributed observations
without an unrequested rerating; an explicitly authorized first-correction
comparison explains both reviewed pieces and any changed levels. Otherwise the
description is about the latest actually reviewed piece. Four separate graphs
retain each reviewed piece and unrated gaps. Supplied practice facts are not
student evidence. The current private format resolves older conflicting scale
or generic-question language. Keep checklist groups, historical weekly states,
four-week date navigation and actual Made-this-run evidence; configured UI is
not evidence that any report was created.

The two school brief jobs have real overlapping source categories, but different
known windows and coverage. Require exact current policies and same-date native
source/output comparison before selecting a retained owner. Never disable by
title. Personal jobs with unknown exact clock, source binding, output or executable
bridge remain prepared candidates only. Historical manual/Friday School Claude
receipts do not establish present schedules or a new message-send grant.

No cutover extends a temporary overnight job's explicit end or resumes paused
inventory/other job-watch work. The coordinator handles the bounded deadline,
freeze and deletion of its own temporary continuation separately.

## Verification

`workflow_cutover.py verify` checks exact candidate identity, artifact hashes,
the single registry binding, preserved policy/rollback evidence and complete
reviewed paragraph mappings. It does not execute, update state or call providers.
The pure `transition` gate rejects missing readback, unsafe two-owner transitions
and uncertain-write replay. Its booleans must come from actual dated evidence;
passing synthetic tests cannot supply them.

Run `python3 -m unittest discover -s ai-ops/runtime/tests -p test_workflow_cutover.py -v`.
The private candidate receipt must also record actual publication, current source
readback, fresh-session bounded trial, and post-update native definition/readback.

Local scheduled work requires the computer awake and desktop app running; cloud
tasks do not inherit a local folder. These are requirements, not proof of a run.
[Official scheduled-task guidance](https://learn.chatgpt.com/docs/automations).
