# Non-school contract invocation and acceptance

These definitions preserve reusable procedures in the existing canonical core. They
are declarative contracts, not activated workers. The catalog validator performs no
account, browser, schedule, document or financial operation. A valid definition is
not evidence that its private bindings, native attachments or destination executor
are available. Use the existing router/controller after its independent acceptance;
do not build a second dispatcher or copy full prompts between providers.

## Start a run from the canonical contract

1. Select the exact `workflow_id` and one permitted action in `definitions/`; read
   that definition, this workflow's section below and its governing source files.
   Current user scope wins over historical instructions. Validate with
   `python3 ai-ops/runtime/workflow_contract.py ai-ops/workflow-contracts/definitions/<file>.json`.
2. Resolve the `private:` references in the existing private registry. They denote
   required bindings, not invented paths or capabilities. Verify source/account
   identity, exact current source revision, authorized output, actual executor
   capability receipt and existing execution owner. A data account is not an executor.
   Scheduled definitions preserve the inventory's exact namespaced `schedule_ref`.
3. Use one actual request ID and one shared lease for the whole attempt. Resolve
   overlapping workflows to the same private resource lease, including independent
   sessions. A declared concurrency key does not itself acquire a lock. Record a
   fingerprint of contract version, source revisions, policy, identity and action.
4. Resolve dependencies before the affected operation. The 300-second source age
   ceiling is a new conservative admission requirement, not an assertion about old
   prompts; re-read source versions immediately before a permitted write. Daily
   birthday evidence additionally requires the same Eastern business date; 86,400
   seconds does not permit yesterday's evidence. `complete` means complete within
   the explicitly verified source scope; `bounded` never means account-wide coverage.
5. Execute only the exact permitted operation under current authorization. Save
   private artifacts in their existing domain, then independently read content,
   destination and version back. Readback failure stops dependent writes. Reconcile
   the same request/receipt before retrying; never mint another ID to evade uncertainty.
6. Report verified output state, exact gap, owner and smallest next action. Continue
   independent readable work. Batch genuinely unanswered choices as short numbered
   questions; an actual answer resumes dependent work. Silence is not approval.

Default rollback for these report/draft contracts: keep prior complete artifacts,
source versions and receipts; withdraw an unaccepted candidate without overwriting
its history. No contract rolls back live schedules, manuscript prose, grades or
financial records automatically. The coordinator owns any authorized schedule
cutover: preserve the original definition, validate destination output/timezone,
then disable the old owner immediately before enabling one replacement and read
both states back. Unknown delivery or ownership retains the existing owner and blocks
cutover. Current school routines remain on their existing Mac/executor.
