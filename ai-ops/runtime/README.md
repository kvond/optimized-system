# Local provider-neutral foundation

This is a local, tested library, not a deployed service, worker, provider integration or schedule. No model/network calls are present. SQLite state stays private and must never enter GitHub. JSON contracts/configuration contain no credentials. The example enables only a synthetic deterministic route; it does not grant school-data or paid-provider authority.

`foundation.py` implements source-revision/inputs/contract/route/privacy-keyed cache, success-only reuse, explicit UTC expiry, scoped invalidation, SQLite serialized budget reservations, idempotent settlement, bounded routing, and owned POSIX process-group stopping. All dollar amounts use integer microdollars internally. Unknown budget and exhausted budget fail closed. Estimates are bounds supplied by a future approved adapter, not price evidence. Actual overruns are recorded and block subsequent spending; a request cannot guarantee its provider price from an estimate. Reservations remain charged against availability across uncertain outcomes and process crashes; cancel only a proven unstarted execution. Provider adapters must not dispatch until their reservation commits.

Cache partitioning prevents accidental cross-partition lookup, but this single-process library is not an authentication boundary: callers need independently enforced authorization, private state files and storage protection. Source revision IDs must come from verified source metadata. Failed outcomes remain stored for diagnostics but are never reusable as successful results. Retention of failures/private payloads requires an approved retention policy. SQLite is appropriate for a single local writer/shared local disk, not a shared network filesystem or concurrent Cloud Run replicas.

Routing chooses an enabled sufficient deterministic route first; otherwise the cheapest sufficient eligible route. Capabilities and privacy partitions are explicit operator-supplied allowlists, not model self-judgments. Routes that are disabled or in another partition cannot be selected. Schema files are interchange contracts, not an installed JSON Schema validator; runtime primitives enforce their own requirements.

`run_bounded` rejects naive dates, expired deadlines and insufficient shutdown margin. It reserves cleanup time before the deadline, polls both aware UTC and monotonic elapsed time, starts a new owned process group, then attempts TERM/KILL on completion and timeout. Output is discarded to avoid unbounded pipes/private transcript storage. No shell is used. It also stops ordinary descendants left behind by a normally exiting leader. Tests verify descendants cannot write a delayed marker. On macOS a final group KILL can return EPERM after TERM and leader exit; this is explicitly returned as `cleanup_confirmed=false` with `signal_errors`, never represented as verified cleanup. Treat that result as requiring reconciliation, and launch no additional work. Process-group escape, setuid children, kernel scheduling delays and OS signal denial require a container/cgroup or equivalent supervisor for an enforceable hard deadline; this library does not claim that guarantee. A hard stop must be applied by the parent to every owned operation, including cloud/provider work, not just local child processes.

Run: `python3 -m unittest discover -s ai-ops/runtime/tests -v` from the repository root. Tests use synthetic data and local temporary processes/files only.

## Minimal cloud continuation

Reuse the Personal Hub pattern: one authenticated API, explicit service identity, private persistent state and a narrow optional MCP interface. Current inventory proves two existing Ready Personal Hub services and Firestore presence, not safe application authentication or deployment acceptance. The MCP service has public Run invocation with a path-token reference; verify authorization before reuse. Keep school operations and existing scheduled ownership untouched. Do not deploy this SQLite file to an ephemeral Cloud Run filesystem. A future approved cloud adapter should implement the same cache/budget transaction contracts in Firestore, with atomic source-version conditions, per-privacy storage/authorization, idempotent requests, and provider receipt reconciliation. Apply max-instance/request limits and a fail-closed budget cap. External hard-deadline enforcement and cancellation/readback must be verified before an autonomous cloud worker is enabled. No new service, scheduler, key or billing scope is required for this local foundation.

Shutdown receipts are constructed only after the final process-group signal and bounded reap attempt. Reaping uses only the remaining UTC/monotonic deadline budget; a 50ms reap margin is reserved inside the cutoff. If the leader cannot be reaped in that interval, `reap_confirmed=false` and `cleanup_confirmed=false` require reconciliation. OS scheduling, process creation, signal syscalls and Python scheduling can still overshoot wall-clock boundaries; an OS/container supervisor remains necessary for an enforceable absolute cutoff. The reset guard uses supported 0.5-second grace.
