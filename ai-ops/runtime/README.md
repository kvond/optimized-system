## Preserved foundation and tools

This is a local, tested library, not a deployed service, worker, provider integration or schedule. The core foundation itself makes no model/network calls; the separately documented public DOE reader below performs bounded HTTP reads. SQLite state stays private and must never enter GitHub. JSON contracts/configuration contain no credentials. The example enables only a synthetic deterministic route; it does not grant school-data or paid-provider authority.

`foundation.py` implements source-revision/inputs/contract/route/privacy-keyed cache, success-only reuse, explicit UTC expiry, scoped invalidation, SQLite serialized budget reservations, idempotent settlement, bounded routing, and owned POSIX process-group stopping. All dollar amounts use integer microdollars internally. Unknown budget and exhausted budget fail closed. Estimates are bounds supplied by a future approved adapter, not price evidence. Actual overruns are recorded and block subsequent spending; a request cannot guarantee its provider price from an estimate. Reservations remain charged against availability across uncertain outcomes and process crashes; cancel only a proven unstarted execution. Provider adapters must not dispatch until their reservation commits.

Cache partitioning prevents accidental cross-partition lookup, but this single-process library is not an authentication boundary: callers need independently enforced authorization, private state files and storage protection. Source revision IDs must come from verified source metadata. Failed outcomes remain stored for diagnostics but are never reusable as successful results. Retention of failures/private payloads requires an approved retention policy. SQLite is appropriate for a single local writer/shared local disk, not a shared network filesystem or concurrent Cloud Run replicas.

Routing chooses an enabled sufficient deterministic route first; otherwise the cheapest sufficient eligible route. Capabilities and privacy partitions are explicit operator-supplied allowlists, not model self-judgments. Routes that are disabled or in another partition cannot be selected. Schema files are interchange contracts, not an installed JSON Schema validator; runtime primitives enforce their own requirements.

`run_bounded` rejects naive dates, expired deadlines and insufficient shutdown margin. It reserves cleanup time before the deadline, polls both aware UTC and monotonic elapsed time, starts a new owned process group, then attempts TERM/KILL on completion and timeout. Output is discarded to avoid unbounded pipes/private transcript storage. No shell is used. It also stops ordinary descendants left behind by a normally exiting leader. Tests verify descendants cannot write a delayed marker. On macOS a final group KILL can return EPERM after TERM and leader exit; this is explicitly returned as `cleanup_confirmed=false` with `signal_errors`, never represented as verified cleanup. Treat that result as requiring reconciliation, and launch no additional work. Process-group escape, setuid children, kernel scheduling delays and OS signal denial require a container/cgroup or equivalent supervisor for an enforceable hard deadline; this library does not claim that guarantee. A hard stop must be applied by the parent to every owned operation, including cloud/provider work, not just local child processes.

Run: `python3 -m unittest discover -s ai-ops/runtime/tests -v` from the repository root. Tests use synthetic data and local temporary processes/files only.

## Minimal cloud continuation

Reuse the Personal Hub pattern: one authenticated API, explicit service identity, private persistent state and a narrow optional MCP interface. Current inventory proves two existing Ready Personal Hub services and Firestore presence, not safe application authentication or deployment acceptance. The MCP service has public Run invocation with a path-token reference; verify authorization before reuse. Keep school operations and existing scheduled ownership untouched. Do not deploy this SQLite file to an ephemeral Cloud Run filesystem. A future approved cloud adapter should implement the same cache/budget transaction contracts in Firestore, with atomic source-version conditions, per-privacy storage/authorization, idempotent requests, and provider receipt reconciliation. Apply max-instance/request limits and a fail-closed budget cap. External hard-deadline enforcement and cancellation/readback must be verified before an autonomous cloud worker is enabled. No new service, scheduler, key or billing scope is required for this local foundation.

Shutdown receipts are constructed only after the final process-group signal and bounded reap attempt. Reaping uses only the remaining UTC/monotonic deadline budget; a 50ms reap margin is reserved inside the cutoff. If the leader cannot be reaped in that interval, `reap_confirmed=false` and `cleanup_confirmed=false` require reconciliation. OS scheduling, process creation, signal syscalls and Python scheduling can still overshoot wall-clock boundaries; an OS/container supervisor remains necessary for an enforceable absolute cutoff. The reset guard uses supported 0.5-second grace.

## Compact context without model calls

`python3 ai-ops/runtime/knowledge.py "cost cutting cheapest model budget" --max-words 400 --max-bundles 2` emits ranked whole-paragraph excerpts from the reviewed knowledge bundles, including source identifiers, provenance and hashes. The default text output has an exact whitespace-word cap including those metadata headers. Add `--format json` for diagnostics: the `context` field has the cap; the JSON envelope is extra and should not be used wholesale as a prompt. Words are not model tokens, and reductions are not measured dollar savings.

The CLI verifies every bundle hash/privacy classification and every declared local source hash before producing context. Raw original sources are hashed only and never emitted. Explicitly marked local-only audit sources must be accessible at their manifest paths; an unavailable or changed source fails closed rather than being treated as portable. Live receipt metadata is read and fingerprinted, but current remote source content is not verified by this offline tool. Its manifest is trusted operator configuration, not a signature or authentication boundary. It rejects credential-shaped strings and unsafe paths; a declared privacy class and pattern scan are not a general secret detector. A short excerpt is not a complete grading/workflow contract: follow the full source before acting.

This command reduces repeated prompt input by deterministic retrieval; it creates no API request, provider adapter, schedule, network activity or runtime database. Tests: `python3 -m unittest discover -s ai-ops/runtime/tests -p test_knowledge.py -v`.

Historical source snapshots are verified at their explicitly declared local-only manifest paths. The original decisions source is preserved in the encrypted archive, outside Git; the CLI emits its path/hash but never the original source text. The optional `--source-root` permits operator-selected original checkouts only when a declared repository-relative source is missing/changed and the alternate bytes exactly match its expected SHA. It never silently updates a hash. A fresh clone without these private local sources fails closed rather than claiming portable verification.

Measured October 12 against all 11 existing bundles (2,863 whitespace words), using a 400-word context cap and at most two bundles:

| Query | Selected context words, including provenance/hash headers | Input reduction |
|---|---:|---:|
| Cost cutting / cheapest model / budget | 391 | 86.34% |

| Writing voice / Substack prose | 393 | 86.27% |

These measure actual deterministic text input reduction, not tokenizer counts, dollar savings or live job-monitoring acceptance. Job monitoring retrieves existing workflow rules; it does not invent a missing full job contract. Seven targeted tests pass, including explicit historical-source byte matching and per-bundle receipt association after ranking. At that October 12 checkpoint, the prior complete runtime suite passed 57 tests in 2.749 seconds and the vacancy checkpoint passed 70 tests in 3.539 seconds. These are historical totals, not the October 14 integration count.

## Public vacancy comparison

`vacancies.VacancyGate` accepts normalized evidence from an independently verified source adapter and explicit per-workflow `Grant` objects. It writes private history and receipts under the resolved encrypted state path. Anonymous public pages require `requires_authentication=False`; private grants default to requiring authentication. Incomplete reads return blocked/unknown counts and preserve prior state. No candidate profile/matching, fetcher, schedule or cloud bridge is included. See [bounded acceptance](../reports/vacancy-gate-2026-10-12.md) and [exact receipt](../reports/vacancy-gate-acceptance-2026-10-12.json). The existing cloud task has a saved generic repeat rule; it has no verified access to this local database.

## Bounded public DOE HTTP source

`doe_source.read_source()` fetches the fixed public DOE location filter and the posting-script URL explicitly declared by that page. It parses literal HTML without executing JavaScript and holds incomplete, mismatched or unavailable reads. Approve its exact `GRANT` before passing `result.read` to `VacancyGate`; no candidate scope or cloud schedule is granted by this API. See [source adapter evidence](../reports/doe-source-adapter-2026-10-12.md) and [ordinary HTTP-to-encrypted-state acceptance](../reports/doe-source-gate-acceptance-2026-10-12.json). The 20-second timeout is a socket timeout, not an absolute execution deadline; callers still require external supervision for execution bounds.
