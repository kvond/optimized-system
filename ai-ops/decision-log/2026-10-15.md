# 2026-10-15 — Slack is the human front door

## Decision

Use Slack as Katherine's readable intake/index for cross-platform AI work. `#optimize-me` is the single intake lane. Existing topical Slack channels are the human-readable work trail. OpenAI and Claude are workers behind one provider-neutral router, not independent state systems or competing bots.

## Boundaries

- GitHub/private repo remembers **how**: code, routing rules, workflow contracts, tests, account maps, runbooks and durable decisions.
- Drive/Docs/Roam remember **the work**: manuscripts, research notes, teaching content and intellectual paper trail.
- Private cache/state remembers **what was already computed**: idempotency, classification cache and usage receipts.
- Slack remembers **where the work stands and where to find it**: intake, categorized handoffs, decisions and accomplishments.
- Deterministic rules and cache precede paid model calls.
- OpenAI and Claude are selected by task/provider policy or explicit user override; no bot-to-bot autonomous loop.
- The Slack gateway may capture/classify/route only. Existing workflow contracts retain authority for external, destructive, student-data, finance, health or other high-impact actions.

## Runtime placement

The gateway belongs in personal project `graceful-fold-341018`, with a dedicated service identity and personal Firestore state. It may read the existing OpenAI/Anthropic API secrets cross-project through secret-level IAM rather than copying credentials. It must not become part of the school data plane merely because the API keys were first stored in the school project.

## Cost policy

Routine classification uses only lowest-sufficient small models after deterministic routing fails. As of this decision, ambiguous operational intake defaults to OpenAI `gpt-6-luna`; ambiguous writing/scholar/research intake defaults to Claude `claude-haiku-5-5`. Explicit `openai:` and `claude:` overrides are supported. Stronger models are not part of the intake gateway.

## Safety / anti-friction rule

One front door, one router, one cache/state owner. Do not create a second Slack listener, duplicate task register, vendor-specific history repository, or parallel provider-specific routing service. Sensitive intake is held rather than forwarded or sent to an API.
