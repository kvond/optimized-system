# Renew lesson slides

This skill applies the standard; it does not hold it. The standard is
`skills/vt-skill/reference/17-lesson-renewal.md` (§17), with
`reference/16-restore-enhance-codes-agenda.md` (§16) for legacy codes/link history.
Read §§17.7, 17.9 and **17.13** fresh each run. As of November 3, 2026:
**VT Questions Teaching Notes, not lesson Agendas, are the instructional source of truth.**
This workflow no longer runs a blanket retrospective repair of older decks. Do
not repair an old deck or add what-if/conflict slides by quota. The central
Skills Page is authoritative when accessible; GitHub updates require sync verification.

## One deck (the deck Katherine has open)

1. Identify the exact active/new native Google Slides deck by its matching
   `VT Questions Teaching Notes` document and file ID; verify course and
   lesson identity against the live source. Consult the legacy Agenda only if
   a surviving downstream caller requires it, not as instructional authority.
   If Katherine is editing the deck right now, only propose; do not write.
2. Before editing an explicitly authorized active/new deck, produce the defect
   list required by §17.11 and inventory every applicable gap against §17.1–17.11,
   slide by slide. Older decks are archival candidates, not a renovation queue. That includes every
   "Relates to me" page, each student-response mode, every run of two or more writing
   slides, pictures illustrating each VT difference/contrast (add them where
   absent, §17.7 and §6), before/during/after-discernment titles, and activity-aware
   90-minute day divisions. Record deferred teacher-edited decks; do not audit only
   a sample. Apply §17.10 to student-facing wording on all slide types, keeping
   clear wording and the scientific reasoning demand intact.
3. Make the smallest changes that close the gaps. Take a fresh revision check before
   writing, and keep originals, media, student copies, codes unrelated to §17, and
   grades unchanged.
4. Run §17.6 together with §17.11's course-specific, teacher-pack and paper-revision
   processability checks, and report exactly what passed, with the deck link and remaining owner
   actions. Follow §17.9 for authorized release order and school-account readback;
   distinguish reviewed-deck readiness from verified VT-notes/Schoology delivery, with any still-used Agenda caller independently checked.

## A batch of active/new lessons (not an older-deck repair sweep)

- **One writer per deck.** Each deck is claimed by one agent in #work-que before any
  write, following the #parallel-agents process (issue, file claim, draft PR for repo
  changes). Routine repository merges follow [review and merge](../../ai-ops/review-and-merge.md);
  classroom deck publishing and release keep their existing authorization and acceptance gates.
- **Pilot first:** one deck per course passes §17.6 and Claude's review before the
  rest of that course is dispatched.
- **Order within a course:** current and forthcoming lessons only, from verified
  VT teaching notes and the actual teaching calendar. Do not reopen earlier
  decks just because a renewal checklist item is absent.
- **A&P** preserves original-source coverage for current/new lesson construction;
  work on its verified native current deck, not an obsolete PowerPoint or draft. Coordinate with the open Anatomy release tasks so the same deck is never
  written twice.
- **Mechanical checks** (sharing per §17.5, link checks per §17.4) may run as one
  separate sweep across all decks, because they don't touch slide content.

Report each finished deck in the #vt-decks thread for that course, and post a summary
in #finished. A plan, a claim or a local check is not completion.

## Retire older decks and superseded agendas (new policy 2026-11-03)

- **No older-slide repairs.** Match each predecessor teacher-owned slide deck to
  a verified current native Google Slides version. Move the predecessor into a
  school Drive `~delete` holding folder only after checking that its unique
  content is preserved and no live lesson, student-copy or automation caller
  still depends on the old file. A `.pptx` with a verified matching Google
  Slides update is a candidate. Never sweep up student work copies.
- Per-lesson `_AGENDA` documents may move once matching VT Questions Teaching
  Notes cover the teaching directions and resource links. The master Agenda
  spreadsheet remains temporarily for surviving administrative and code
  consumers until those dependencies are migrated and verified.
- Record file ID, original parent, successor URL, destination folder and move
  result; distinguish moved, held, unmatched and inaccessible. Do not permanently
  delete or edit legacy slides to improve them.
- When preparing new or active lessons, check §17.7's distinctions: what-if
  questions mainly belong to contingent teacher dialogue; a genuine conflict
  case requires two already-taught critical aspects pulling toward different
  answers, and may intentionally be absent. Document the reasoning in the VT
  teaching note rather than adding a token slide.
