# School lesson audit

An accessible file is not necessarily the right lesson. A deck named “VT” is not necessarily integrated or ready to teach. Report these separately.

## Authority and scope

- Default to read-only audit. A request to repair authorizes only its specified targets and changes. Work one week or one bounded change at a time, preserving all native file IDs, grade history, student copies, and source attribution. Do not replace masters through PPTX round trips.
- Never access `answerableteaching.com`, including redirects to that domain. Use the live school Drive manual. Do not read student submissions or grade records for this audit.
- Exclude Biology Week/Cycle 02 content unless the user explicitly grants a narrower exception. A link-only exception does not permit editing or recoding it. Biology Public is the drafting source; Biology Materials is recovery/reference, not an interchangeable master.
- Use installed Google Drive and the relevant Docs, Sheets, Slides/Presentations skills for access, trusted reads and native edits. Read `school-slides-sweep` and its `references/sources-and-state.md` for source IDs and manual-baseline mechanics. Their sweep-only restrictions do not erase a current explicit repair request, but no old approval expands a new request.
- Read [references/audit-gates.md](references/audit-gates.md) completely before a full audit. For a narrow repair, read it to identify the affected gates; do not represent a narrow check as a full audit.
- Reuse approved connections. Owner, connector and student access are distinct. Do not change sharing or authenticate a new account simply to clear an audit finding. Report discrepancies before a destructive change; resolve exact targets and authority first. Never delete a source PPT merely because a similarly named native deck exists.

## Run and record the gates

Use the detailed reference for each lesson. Capture exact file ID, native revision, slide IDs and source evidence, not just titles. A full course audit includes every in-scope discovered master, including unchanged decks; a monthly sweep can select changed items.

Keep distinct statuses for:

- identity/pacing and folder placement;
- source-material coverage;
- enhancement;
- integrated VT and reasoning quality;
- student AI revision support;
- manual-compatible feedback codes;
- visual presentation;
- links and intended-audience access;
- Form/folder and LMS routing.

Use `verified`, `needs-repair`, `unverified`, `blocked`, or `not-applicable` with a reason and evidence. A filename, HTTP 200, marker count or successful automation run alone cannot set `verified` for a whole lesson. A completed audit may contain unresolved findings; that is not a release pass.

## Repair and verify

Apply only inspected, authorized changes. Save exact before/after names, parents, native text/notes, IDs and revisions as appropriate. Use fresh native reads and required revision checks; stop the affected write on concurrent changes. Keep a single writer per deck/week. Independent agents may inventory or review disjoint targets only when delegation is explicitly authorized; do not share browser control concurrently.

Within one coordinated run, the coordinator may supply a timestamped complete manual/Agenda read and its verified extracts to bounded reviewers. Reviewers must identify the supplied revision and the rules actually used, and must not claim an independent live read or release pass. Recheck source freshness before writes and final sign-off; a cached manifest alone does not establish current authority.

A snapshot-bounded review may finish its specified checks while full inventory, manual or visual gates remain unverified. Label that profile and its omissions explicitly; it is not a whole-unit audit or a waived release gate.

For folder moves, compare source/destination permissions and explain any material access effect before proceeding. Re-read the exact file and its parent after the move. **Restoring a file from trash may place it in the owner's private My Drive and remove inherited access.** Verify the actual location and access; returning it to a verified original shared lesson folder is different from creating new broad sharing.

Re-read all changed targets, verify retained links/notes/codes, and render changed slides using the presentation skill. A note-only repair requires exact note/range/style checks plus proof that visible page content did not change. Full lesson release still requires a whole-deck visual and semantic pass.

Update checkpoints only for successful observations and verified writes. Preserve unresolved findings and historical records. Before a release pass, recheck the final deck revision and relevant manual-rule fingerprint; any intervening relevant edit invalidates that pass.

Save a concise user-facing report with scope/counts, completed repairs, actual versus unverified gates, exact discrepancies, affected weeks and next actions. Retain a per-deck register and link-occurrence appendix so another run can resume. Do not claim Schoology, IC, Forms, or student-access checks that were not performed.

Annual audits inspect all slides and all link-bearing surfaces, not only changed decks. Monthly sweeps detect additions and changes, and a relevant manual update queues a final code recheck. A skill does not schedule itself or keep a computer awake. Inspect/update an existing automation only when scheduling is requested; do not recreate the canceled 7 AM/2 PM reminders.
